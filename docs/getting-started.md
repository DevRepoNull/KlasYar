# 🚀 راهنمای شروع سریع کلاس‌یار (Getting Started)

به راهنمای گام‌به‌گام راه‌اندازی و اجرای **کلاس‌یار** خوش آمدید. این راهنما به‌گونه‌ای طراحی شده که حتی اگر تجربه‌ای در برنامه‌نویسی یا کار با ترمینال نداشته باشید، بتوانید ظرف چند دقیقه برنامه را روی کامپیوتر خود نصب و استفاده کنید.

---

## 👥 این راهنما برای چه کسانی است؟

- **معلمان، اساتید و مدرسان:** که می‌خواهند بدون درگیر شدن با مفاهیم فنی، برنامه را روی سیستم خود اجرا و از کلاس‌ها و جلساتشان میزبانی کنند.
- **کاربران خانگی:** که به دنبال یک دفتر کلاسی و برنامه‌ریزی امن، آفلاین و کاملاً خصوصی هستند.
- **توسعه‌دهندگان و علاقه‌مندان:** که می‌خواهند پروژه را در محیط محلی بررسی یا اجرا کنند.

## 💻 راهنمای نصب بر اساس سیستم‌عامل

لطفاً بخش مربوط به سیستم‌عامل خود را انتخاب و مراحل را دنبال کنید:

### 🪟 ۱. سیستم‌عامل ویندوز (Windows)

#### الف) نصب خودکار با Windows Terminal / PowerShell (روش پیشنهادی):
۱. کلید‌های ترکیبی `Win + X` را فشار داده و **Terminal** یا **PowerShell** را باز کنید.  
۲. دستورات زیر را برای نصب Node.js و Git از طریق ابزار رسمی ویندوز (`winget`) اجرا کنید:

```powershell
winget install OpenJS.NodeJS.LTS
winget install Git.Git
```
۳. پس از پایان نصب، پنجره ترمینال را ببندید و مجدداً باز کنید تا متغیرهای سیستمی اعمال شوند.

#### ب) نصب با فایل نصبی (GUI Installer):
- فایل نصبی **Node.js LTS** را از [nodejs.org](https://nodejs.org) و **Git** را از [git-scm.com](https://git-scm.com/downloads) دانلود و مراحل استاندارد «Next» را طی کنید.

#### ⚠️ حل مشکل خطای اجرای اسکریپت‌ها در PowerShell (ExecutionPolicy):
اگر هنگام اجرای دستورات با خطایی مشابه `File ... cannot be loaded because running scripts is disabled on this system` مواجه شدید، دستور زیر را یک‌بار در PowerShell اجرا کنید:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```
سپس حرف `Y` را تایپ کرده و `Enter` بزنید.

---

### 🍎 ۲. سیستم‌عامل مک (macOS)

#### الف) با استفاده از Homebrew (روش سریع و استاندارد):
۱. برنامه **Terminal** را از مسیر Applications > Utilities باز کنید.  
۲. اگر [Homebrew](https://brew.sh) نصب نیست، دستور نصب آن را اجرا کنید:
```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```
۳. سپس با یک دستور ساده Node.js و Git را نصب کنید:
```bash
brew install node git
```

#### ب) با فایل نصبی گرافیکی:
می‌توانید بسته‌های نصب `.pkg` را مستقیماً از وب‌سایت [Node.js](https://nodejs.org) و [Git](https://git-scm.com/downloads) دانلود و نصب نمایید.

> **نکته معماری Apple Silicon (M1/M2/M3) در برابر Intel:**  
> بسته‌های رسمی Node.js و ابزار Homebrew به‌صورت بومی (Universal Binary / ARM64) اجرا می‌شوند و هیچ تداخلی ایجاد نمی‌کنند. در مک‌های جدید نیاز به تنظیمات خاص یا فعال‌سازی Rosetta نخواهید داشت.

---

### 🐧 ۳. سیستم‌عامل لینوکس (Linux - Ubuntu / Debian و مشتقات)

#### الف) استفاده از nvm (توصیه اکید):
مخازن رسمی اوبونتو و دبیان معمولاً نسخه‌های قدیمی Node.js را دارند. بهترین و بی‌دردسرترین روش، استفاده از `nvm` (Node Version Manager) است:

```bash
# ۱. نصب nvm
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash

# ۲. بارگذاری مجدد تنظیمات شل
source ~/.bashrc

# ۳. نصب و فعال‌سازی آخرین نسخه پایدار Node.js
nvm install --lts
nvm use --lts

# ۴. نصب Git (در صورت عدم وجود)
sudo apt update && sudo apt install git -y
```

#### ب) استفاده از مخازن پیش‌فرض توزیع:
در صورت تمایل می‌توانید بسته‌های مخزن سیستم را نصب کنید:
```bash
sudo apt update
sudo apt install nodejs npm git -y
```
*(توجه: حتماً با اجرای `node -v` اطمینان حاصل کنید که نسخه حداقل ۱۸ باشد).*

## 🔐 اولین ورود و راه‌اندازی (First Run Onboarding)

هنگامی که برای نخستین بار کلاس‌یار را در مرورگر باز می‌کنید:
1. **تنظیم رمز عبور مدیریت محلی (Admin Password):**  
   صفحه خوش‌آمدگویی و ورود ظاهر می‌شود. یک نام کاربری (پیش‌فرض: `admin`) و رمز عبور مطمئن انتخاب کنید. این رمز عبور با الگوریتم **PBKDF2 و SHA-256** به صورت رمزنگاری‌شده در حافظه مرورگر شما نگهداری می‌شود و هیچ فرد دیگری حتی در صورت دسترسی فیزیکی کوتاه‌مدت به رایانه شما نمی‌تواند سوابق شاگردانتان را بدون رمز مشاهده کند.
2. **انتخاب تم و پالت رنگی دلخواه:**  
   از میان پالت‌های لوکس (**زمرد**، **نیمه‌شب**، **غروب** یا **تک‌رنگ**) و تم تاریک/روشن، حالت بصری متناسب با سلیقه کاری خود را برگزینید.
3. **قفل سریع (Lock Screen):**  
   در هر زمان که پشت سیستم نیستید، با کلیک روی آیکون قفل در بالای صفحه یا منوی تنظیمات، صفحه برنامه قفل می‌شود تا امنیت داده‌ها محفوظ بماند.

## 🔄 راهنمای جامع به‌روزرسانی و ارتقا (How to Update KlasYar)

یکی از سوالات حیاتی مدرسان این است:  
> **«اگر در آینده نسخه‌های جدیدتر و آپدیت‌های پیاپی برای کلاس‌یار بیاید، چطور برنامه را آپدیت کنم و چطور مطمئن شوم اطلاعات کلاس‌هایم پاک نمی‌شوند؟»**

### ۱. اصل بقای داده‌ها در معماری Local-First
تمام اطلاعات کلاس‌ها، جلسات، اسامی دانش‌آموزان و رکوردهای حضور و غیاب در پایگاه داده مستقل مرورگر شما (**IndexedDB**) ذخیره می‌شوند. فایل‌های کد جاوااسکریپت، استایل‌ها و کامپوننت‌ها جدا از محل ذخیره‌سازی داده‌ها هستند. بنابراین **به‌روزرسانی کدهای برنامه به هیچ وجه دیتابیس را پاک نمی‌کند.**

### ۲. گام طلایی پیشگیرانه: خروجی فایل پشتیبان (Export JSON)
همواره پیش از هر ارتقای عمده، طبق این دستورالعمل ساده یک نسخه پشتیبان بگیرید:
1. از منوی کناری وارد بخش **تنظیمات** (`/settings`) شوید.
2. برگه **داده‌ها** را انتخاب کنید.
3. روی دکمه **«خروجی پشتیبان (Export JSON)»** کلیک کنید تا فایل پشتیبان روی سیستم شما ذخیره شود.  
*(این فایل را می‌توانید در هر زمان یا روی هر دستگاه دیگری با دکمه «بازیابی پشتیبان» فراخوانی کنید).*

### ۳. مراحل آپدیت برای کاربران Git / ترمینال:
اگر پروژه را روی کامپیوتر خود کلون کرده‌اید، ارتقا فقط چند ثانیه طول می‌کشد:

```bash
# ۱. رفتن به پوشه کلاس‌یار
cd klasyar

# ۲. دریافت آخرین تغییرات نسخه جدید از گیت‌هاب
git pull origin main

# ۳. به‌روزرسانی وابستگی‌ها و پکیج‌ها
npm install

# ۴. اجرای آزمون‌های سلامت برنامه برای اطمینان از صحت عملکرد
npm test

# ۵. اجرای مجدد محیط
npm run dev
```

### ۴. نحوه ارتقای خودکار پایگاه داده (Schema Migration)
سیستم پایگاه داده کلاس‌یار بر پایه‌ی **Dexie.js Migration** ساخته شده است. وقتی نسخه جدیدی از برنامه با جداول یا ایندکس‌های جدید منتشر می‌شود، مرورگر شما در اولین اجرا نسخه قدیمی دیتابیس را به نسخه جدید ارتقا می‌دهد، بدون اینکه داده‌های پیشین شما دستکاری یا حذف شوند.

## 📦 ساخت نسخه نهایی و پایدار (Production Build)

اگر می‌خواهید برنامه را برای استفاده همیشگی یا استقرار در وب‌سرور بسازید:

```bash
npm run build
```
این دستور کدهای پروژه را کامپایل، فشرده و بهینه‌سازی کرده و در پوشه‌ای به نام **`dist/`** قرار می‌دهد.

برای مشاهده پیش‌نمایش نسخه بیلد شده:
```bash
npm run preview
```

> **⚠️ نکته مهم:**  
> فایل `index.html` موجود در پوشه `dist/` را نمی‌توان مستقیماً با دابل کلیک باز کرد؛ برنامه‌های مدرن وب به دلیل مسائل امنیتی (CORS و بارگذاری ماژول‌ها) باید توسط یک وب‌سرور محلی (مانند `npm run preview` یا افزونه Live Server یا Nginx) ارائه شوند.

## 🛑 نحوه متوقف کردن برنامه

- برای خاموش کردن سرور محلی، در پنجره ترمینالی که برنامه در آن در حال اجراست، کلیدهای **`Ctrl + C`** را بفشارید.
- **تفاوت توقف سرور با حذف اطلاعات:**  
  توقف سرور توسعه یا بستن مرورگر به هیچ وجه اطلاعات کلاس‌ها و جلسات شما را پاک نمی‌کند. تمام اطلاعات در حافظه مرورگر شما (**IndexedDB**) با امنیت کامل باقی می‌مانند و با اجرای مجدد `npm run dev` در دسترس خواهند بود.

---

## 🗑️ پاک کردن کامل داده‌ها (Reset Data)

اگر به هر دلیلی قصد دارید کل اطلاعات برنامه را به حالت اولیه برگردانید:

1. **روش اول (از داخل نرم‌افزار):**  
   ورود به بخش **تنظیمات** (`/settings`) > برگه **داده‌ها** > کلیک روی دکمه **حذف کامل داده‌ها**.
2. **روش دوم (از طریق ابزار مرورگر DevTools):**  
   - کلید `F12` را در مرورگر بفشارید تا DevTools باز شود.
   - به تب **Application** (در فایرفاکس **Storage**) بروید.
   - از ستون سمت چپ گزینه **IndexedDB** را باز کرده و پایگاه‌داده‌های مربوط به `klasyar` را پیدا و روی **Delete database** کلیک کنید.

## 🛠️ رفع مشکلات رایج (FAQ & Troubleshooting)

اگر در هر یک از مراحل با مشکلی مواجه شدید، جدول زیر راه‌حل مشکل شما را در اختیارتان می‌گذارد:

| مشکل یا پیام خطا | دلیل بروز | راه‌حل فوری |
| :--- | :--- | :--- |
| **`command not found: node`** یا **`node is not recognized`** | نودجی‌اس روی سیستم نصب نیست یا مسیر آن در متغیر محیطی PATH اضافه نشده است. | Node.js را از [nodejs.org](https://nodejs.org) مجدداً نصب کنید و پس از نصب، ترمینال را ببندید و دوباره باز کنید. |
| **`EACCES: permission denied`** (در مک یا لینوکس) | مجوزهای دسترسی npm بدون دسترسی ریشه یا تنظیمات اشتباه پوشه global. | از `nvm` برای مدیریت Node استفاده کنید تا نیازی به مجوز root نباشد، یا مالکیت پوشه را تصحیح کنید: `sudo chown -R $USER ~/.npm` |
| **خطای اشغال بودن پورت (`Port 5173 is in use`)** | برنامه دیگری یا یک نمونه قبلی از کلاس‌یار در حال استفاده از این پورت است. | اجرای سرور روی یک پورت دیگر با دستور: <br>`npm run dev -- --port 5174` |
| **صفحه سفید بعد از بیلد و اجرا روی GitHub Pages** | مسیر پایه (Base Path) برای زیرمسیر در `vite.config.ts` تنظیم نشده است. | در فایل `vite.config.ts` مقدار `base: '/klasyar/'` (مطابق نام مخزن خود) را اضافه و دوباره `npm run build` بگیرید. |
| **فونت فارسی لود نمی‌شود یا متن‌ها به شکل فونت پیش‌فرض سیستم نمایش داده می‌شوند** | فایل فونت در مسیر مناسب لود نشده یا ارتباط شبکه مسدود است. | فونت وزیرمتن به‌صورت فایل محلی در `public/fonts/` قرار دارد. بررسی کنید که فایل `public/fonts/Vazirmatn-Variable.woff2` موجود باشد و در CSS از `font-display: swap` استفاده شده باشد. |
| **داده‌ها و کلاس‌ها بعد از بستن یا پاک‌کردن کش مرورگر پاک شده‌اند** | کش عمیق مرورگر پاک شده یا از حالت ناشناس (Incognito/Private) استفاده شده است. | برنامه‌های کلاینت‌محور داده‌ها را در حافظه همان مرورگر ذخیره می‌کنند. برای جلوگیری از دست رفتن داده‌ها، به‌صورت دوره‌ای از بخش **تنظیمات > داده‌ها > خروجی پشتیبان (Export JSON)** فایل پشتیبان تهیه کنید. |
